# LED 배선도면 (tools/led-wiring)

SOL MEDIA LAB의 LED 설치 후 LAN·POWER 배선도와 자재 수량표를 만드는 정적 웹 도구.
서버 없이 브라우저에서만 동작하고, 기존 엑셀(`라인.xlsx`, `역삼멀티캠퍼스 라인.xlsx`) 계산 로직을 옮긴 것이다. UI 문구는 한국어.

## 실행 / 테스트

- 테스트: `cd tools/led-wiring && npm test` (Node 내장 `node --test`, 외부 의존성 없음)
- 화면 테스트: `start.bat` 더블클릭 → `http://localhost:8765/index.html` (`serve.py`는 캐시를 끄는 로컬 서버).
  `file://`로 직접 열면 `data/pixel.json`을 못 읽는다.
- 엑셀 출력 테스트는 Python `openpyxl`이 있으면 파일을 열어 검증하고, 없으면 그 항목만 건너뛴다.
- 빌드 과정 없음. 순수 HTML/CSS/JS(ES 모듈).

## 구조

| 파일 | 역할 |
|---|---|
| `src/config.js` | **규칙/기본값은 여기 한 곳에서만** 바꾼다 (포트 픽셀 한도, POWER 기준, 아시바 규격, 기본 패턴, 최대 캐비닛 수) |
| `data/pixel.json` | 피치별 해상도·캐비닛 규격별 1박스 수량 (엑셀 `pixel` 시트) |
| `src/calc.js` | 계산(캐비닛 수, 해상도, 박스, POWER/랜 포트 수, 아시바). DOM 의존 없음 |
| `src/layout.js` | 격자 배치, LAN 줄 분할/직접 배선, POWER 체인, 패턴 8종 |
| `src/rowplan.js` | 1000 캐비닛 행 배치 편집(이동/나누기/합치기) |
| `src/render.js` | 레이아웃 → SVG 문자열 (화면/PNG/PDF 공용) |
| `src/report.js` | 자재표 데이터 (화면 표/엑셀/인쇄 공용) |
| `src/xlsx.js` | 라이브러리 없는 최소 .xlsx 작성기 |
| `src/export.js` | PNG / 엑셀 / 인쇄 |
| `src/ui.js` | 화면 연결, 입력 저장(URL + localStorage), 직접 그리기 |

계산(`calc`/`layout`)과 화면(`ui`)을 분리해 두었다. 계산 변경은 반드시 `test/`에 테스트를 추가한다.

## 확정된 규칙 (바꾸기 전에 사용자에게 물을 것)

- **LAN은 항상 사각형(ㅁ)으로 계산**한다. 포트 한도는 배선 모양과 무관하게 사각형으로 환산한다.
  직접 그린 같은 LAN의 여러 구간도 전체를 감싸는 사각형으로 환산하며, 그 안의 빈 칸·다른 LAN 소유 칸도 포함한다. 500/1000 혼합 행은 실제 높이별 해상도를 합산한다.
  자동 배선은 사각형으로만 나누며, ㄱ/ㄴ/ㄷ자 모양은 만들지도 추천하지도 않는다. 사용자가 직접 그리는 것은 허용.
- 1포트 한도 650,000픽셀, **3.9피치만 656,000**. **이 숫자(한도, 장수)는 화면 문구·오류 창에 노출하지 않는다.**
  오류 문구는 "LAN N: 한 포트 한도를 넘습니다." / "영역을 줄이거나 다른 LAN 번호로 나누어 그려 주세요."만.
- 피치 선택 6종: 1.5 / 2.6 / 2.6 flexible / 3.9 (indoor), 3.9 / 4.8 (outdoor). `pixel.json`의 키는 `1.5-in`, `3.9-out` 형태. `2.6-flex-in`은 기존 2.6 바로 아래의 WISDOM이며 500×500은 14장/박스, 500×1000은 미정(`null`).
- 1박스 수량: p1.5 500×500=14, p2.6 UNILUMIN=12, WISDOM=14, p3.9 실내 500×500=14·500×1000=7, p3.9 야외 500×1000=12, p4.8 야외 500×500=14. p3.9 야외 500×500은 박스마다 달라 `null`을 유지한다.
- 캐비닛 선택 목록과 세부내역 비고·박스 표는 500×1000을 위에 표시한다(`config.cabinetOptions` 순서). 500×500만 지원하는 제품은 해당 규격만 표시한다. 실제 도면 행 배치의 500 줄이 맨 위에 오는 규칙은 유지한다. 박스 표는 `필요수량 < 출고수량 = 1박스수량 × 출고박스` 형식이며 필요수량과 출고수량이 같으면 `<` 대신 `=`로 표시한다.
- 캐비닛 선택: p1.5, p2.6 UNILUMIN/WISDOM, p4.8은 500×500만 표시한다(`pixel.json`의 `allowedCabinets`). 피치 변경 또는 URL/저장값 복원 시 다른 규격이면 500×500으로 전환하고 행 배치를 초기화한다. p3.9 인도어/아웃도어는 기존 규격 선택을 유지한다.
- 자재 수량표는 `LAN포트 수`·`POWER 포트 수`로만 표시하고 실제 도면 포트 수를 사용한다. 제어기 수량 항목과 전원 그룹 정보·설정은 표시하지 않는다. 화면·오류 안내·도면·내보내기에서 랜선 명칭은 `LAN`으로 통일한다.
  POWER는 500×500을 1장분, 500×1000을 2장분으로 환산한다. 자동 배선은 픽셀과 무관하게 포트당 가급적 20장분 이내(`config.power.autoMaxCabinetsPerPort`)로 나눈다. 혼합 행도 각 캐비닛 크기로 합산한다.
  POWER 직접 그리기는 20장을 넘어도 허용하며 LAN 픽셀 한도를 적용하지 않는다. POWER 포트 수는 실제 도면 포트 수를 따른다.
  POWER 직접 그리기에서 한 포트의 실제 소유 캐비닛이 500×500 환산 20장분을 넘으면 POWER 도면 상단에 경고만 표시한다. 500×1000은 2장분으로 합산하며, 배선을 차단하거나 오류 창을 띄우지 않는다. 20장분 이하로 줄이면 경고는 사라진다.
- 아시바(비계): 가로 1.84m/칸(`1,840 + (칸 수 − 1) × 1,840mm`), 깊이 900mm. 높이는 일반기둥 1,700mm·짧은기둥 900mm에 위아래 연결부마다 노출 핀 25mm를 더한다(`config.scaffold.pinExposedM`). **가로는 LED 가로 이내, 높이는 바닥부터 LED 상단 높이 이내여야 한다.** 아시바는 바닥에서 시작한다. LED 시작 높이는 선택한 LED 단 높이 + 선택한 베이스 40mm(`config.scaffold.baseHeightMm`)이며, 아시바 높이 한도는 LED 세로 + LED 시작 높이다. 단 600mm + 베이스 40mm이면 LED 시작 640mm다. 베이스와 단은 각각 기본 미사용이며 단 사용 시 높이를 0 이상의 숫자로 입력해야 한다.
  일반 2단은 3,425mm, 일반 1단+짧은기둥은 2,625mm, 일반 2단+짧은기둥은 4,350mm다. 자동 단 수·짧은기둥 추가 여부와 수동 지정 높이 초과 판정 모두 핀을 포함한다. 짧은기둥 층은 기둥(칸+1개)과 핀을 추가하고 x바는 추가하지 않는다. 최상단 발판은 기본 제외이며, 발판 행의 비고란에 `상단발판포함` 체크박스로 선택한다. 짧은기둥이 있으면 일반기둥 상단의 발판은 기본 포함하고 짧은기둥 상단만 선택한다. 핀 비고는 `핀높이 25mm`로 표시한다.
  발판 수는 짧은기둥이 없으면 기본 `칸×(일반단−1)`, 상단 포함 시 `칸×일반단`이다. 짧은기둥이 있으면 기본 `칸×일반단`, 상단 포함 시 `칸×(일반단+1)`이다. 4칸×2단은 기본 4개·선택 8개이며, LED 7000×5000의 3칸×2.5단은 기본 6개·선택 9개다.
- 500×1000 캐비닛: 기본은 남는 높이의 500 줄을 맨 위에, 그 아래에 1000 줄을 배치한다. "기본 배치로"도 같은 순서를 사용한다. 사용자가 행 배치를 바꿀 수 있다
  (`rows=500-1000-1000-500-500` 형식). 전체 높이는 같아야 하고 안 맞으면 기본 배치로 돌아간다.

## UI 동작 규칙

- 필요수량이 1박스 수량의 배수로 딱 맞으면 여분 1박스를 추가 출고한다(`config.packing.extraBoxesWhenExact`). 출고수량도 추가된 박스 수에 맞춰 계산한다. 박스에 남는 수량이 있으면 기존 올림 박스 수를 사용하고, 필요수량 0 또는 1박스 수량 미정인 항목에는 여분을 추가하지 않는다. 예: 84장 / 14장 = 출고 7박스·98장.

- 아시바 표의 길이·치수와 관련 오류 안내는 mm 단위로 표시한다. 짧은기둥 항목명과 비고의 명칭은 `아시바(짧은기둥)`으로 통일한다. 부재 수량은 개수이며 길이 단위를 붙이지 않는다.
- 아시바 크기 비고는 `4칸 × 2단 × 1폭` 형식으로 표시한다. 짧은기둥은 표시상 0.5단을 더해 `1.5단`·`2.5단`처럼 표기하며 실제 높이·수량 계산은 기둥과 연결핀 규칙을 그대로 따른다.
- `3D도면 자세히보기` 버튼은 PC·모바일 모두 미리보기 제목 오른쪽에 표시한다. 별도 도면 창에 현재 LED 크기·제품·칸·단·상단 발판 선택을 전달하며 반복 클릭은 같은 도면 창을 재사용한다. 3D 도면도 `calc.js`와 `config.js`의 계산을 사용하며, 구조 안전 검토 완료 도면으로 표현하지 않는다.
- 3D 도면 전면에는 입력한 가로·세로와 제품 두께의 LED 패널을 붙여 표시한다. 배치는 `config.scaffold.ledPanelAlignment`의 중앙·하단 맞춤을 따르며, 캐비닛 구획은 현재 500/1000 혼합 행 순서도 그대로 전달한다. 미확정 두께는 임의 수치 없이 평면으로 표시하고, 패널 뒷면 외형은 개념 표현임을 밝힌다.
- 3D 도면의 `LED 패널 표시` 체크박스는 기본 켜짐(`config.scaffold.showLedPanelDefault`)이며, 해제하면 아시바만 보여 준다. 표시 선택은 도면 URL의 `showPanel`로 유지하고 아시바 수량·상단 발판 선택은 변경하지 않는다.
- 아시바 표의 구분 헤더 위에 `베이스 높이(40mm)` 체크박스와, 간격을 두고 `LED단 높이(mm)` 체크박스·숫자 입력창을 한 묶음으로 표시한다. 단 높이 입력은 단 사용 시에만 활성화하고, 시작·상단 높이를 mm로 안내한다. 선택과 입력은 메인 URL/localStorage 및 3D 도면 링크에 유지한다. 초기화는 두 선택을 해제하고 단 높이도 비운다. 3D에서는 LED 패널만 시작 높이만큼 올리고 아시바는 바닥에 둔다. 내보내기에도 설치 높이 정보를 포함한다.
- 3D에서 LED 단은 파란 박스, 베이스는 노란 박스로 표시한다. 단은 바닥부터 입력한 높이, 베이스는 단 위(단 미사용 시 바닥)에 설정된 높이로 쌓는다. 두 박스는 해당 항목 사용 시에만 표시하며 LED 패널 숨김과는 별개다. 가로·깊이는 설치 위치를 보여 주는 개념 표현이다.
- 초기화는 크기·픽셀피치·캐비닛 규격과 숫자 입력을 비우고, 직접 배선·행 배치·도면·자재표를 지운다. 미선택 입력을 자동으로 채우지 않는다. 필수 입력 전에는 도면을 계산하지 않으며 내보내기는 비활성화한다. 초기화한 빈 상태도 URL/localStorage로 유지한다.
- LAN 번호는 **줄에 고정**: 다른 줄을 지워도 번호가 당겨지지 않는다. 새 줄은 비어 있는 가장 작은 번호.
  LAN·POWER는 새 번호를 건너뛰어 만들 수 없고 기존 번호 또는 가장 작은 빈 번호만 선택한다(`config.lan.sequentialManualNumbers`, `config.power.sequentialManualNumbers`). 목록 번호는 직접 수정하지 않고 번호 뒤 여백·가로 세 줄 손잡이·여백·장수 순서로 표시한다. 손잡이를 드래그하면 위에서부터 1번부터 다시 매기며 같은 포트의 모든 구간이 함께 바뀐다. 삭제만으로는 다른 번호를 당기지 않는다. 순서 변경은 현재 탭에만 적용한다.
- **LAN와 POWER의 배선 기준은 별개다.** LAN 자동 배선은 사각형·픽셀 한도 안에서 포트 수 최소화보다 선택 방향으로 최대한 길게 진행하는 것을 우선한다(`config.lan.autoDirectionPriority`). 가로 패턴은 가로 전체 폭, 세로 패턴은 전체 높이를 우선하고, 한도를 넘으면 선택한 시작점에서 한도까지 연결한 뒤 다음 구간으로 나눈다. 혼합 행은 실제 해상도로 계산하며 각 사각형 내부 경로와 포트 번호는 선택한 시작 모서리를 따른다. POWER의 기존 균등 분할은 별도로 유지한다.
- POWER 자동 배선은 사각형과 환산 장수 기준 안에서 선택 방향의 띠를 우선한다. 분할이 필요하면 가능한 균등하게 나눈다(가로 24장은 20+4가 아닌 12+12). 500/1000 혼합 행은 환산 부하를 기준으로 나눈다. POWER는 포트 수 최소화보다 방향을 우선한다.
- 직접 그리기: 같은 번호로 계속 드래그하면 한 LAN에 구간이 이어진다. "그리는 LAN 번호"를 바꾸거나 "새 LAN"를 누르기 전에는 번호가 넘어가지 않는다.
- 자동에서 직접 그리기로 전환할 때마다 현재 화면에 보이는 해당 배선의 자동 도면을 번호·영역·패턴 그대로 복사해 수정의 출발점으로 사용한다. 이전 직접 배선을 복원하지 않으며 다른 탭의 배선은 유지한다.
- 드래그로 그린 구간 때문에 포트 한도를 넘으면 **도면에 반영하지 않고** 오류 창을 띄운다.
  (설정을 바꿔서 뒤늦게 한도를 넘은 줄은 빨간 점선 + 경고로 표시)
- LAN 탭 / POWER 탭으로 도면을 나눠 보여 준다. PNG는 위에 LAN, 아래에 POWER 도면. PDF는 A4 가로로 LAN·POWER 도면을 각각 한 페이지에 크게 표시한 뒤 자재표를 배치한다. 자재표는 흰 배경에 웹 화면과 같은 2열 구성(세부내역·박스 / 아시바·3D 미리보기 / LAN·POWER 구성)으로 표시하며 행 중간의 페이지 나눔을 피한다. 인쇄 시 미리보기의 현재 시점을 SVG 그림으로 복사해 출력하고 조작 버튼·스크롤바는 표시하지 않는다. 엑셀은 LAN 표 아래에 POWER 표.
- 아래 자재표의 `LAN포트 구성`과 `POWER포트 구성`은 선택된 도면 탭과 관계없이 둘 다 표시한다. 화면의 세부내역·박스·아시바·각 포트 구성은 각각 배경·테두리·안쪽 여백이 있는 별도 영역으로 표시하고 영역 사이에도 여백을 둔다.
- PC 화면(900px 이상)은 아시바 다음 줄에 `LAN포트 구성`을 왼쪽, `POWER포트 구성`을 오른쪽으로 나란히 배치한다. 좁은 화면은 기존 순서대로 세로로 표시한다.
- PC에서는 아시바 표 오른쪽에 현재 설정의 `아시바 3D 미리보기`를 아시바 항목 높이에 맞춰 표시한다. 모바일에서는 아시바 표 아래에 미리보기를 화면 폭에 맞춰 표시한다. 기존 3D 도면의 간단 보기 모드를 재사용하며 드래그 회전을 지원한다. 인쇄에서는 현재 시점의 정적인 그림을 표시한다.
- 모바일 박스 표는 최소 가로 폭을 강제하지 않고 화면 폭 안에 맞춘다. 제목은 필요/수량·출고/수량·1박스/수량·출고/박스, 캐비닛 규격은 × 뒤에서 줄바꿈할 수 있게 하며 좌우 스크롤이 생기지 않도록 한다.
- 세부내역·아시바 표의 열 비율은 구분 25%·수량 40%·비고 35%다. 모바일에서도 구분·수량·비고의 3열 표를 유지하며 비고를 아래줄로 옮기지 않는다.
- 모바일에서는 모든 자재표의 숫자·문구·비고 안에서 필요한 줄바꿈을 허용해 각 항목에 좌우 스크롤이 생기지 않도록 한다. 비고 셀 자체를 다른 행으로 옮기거나 내용을 잘라 숨기지 않는다.
- POWER 탭도 자동·직접 그리기, 패턴 8종, 포트 번호 변경, 새 포트, 되돌리기·모두 지우기를 지원한다. LAN·POWER의 모드·패턴·직접 그린 구간·현재 번호는 별도로 URL/localStorage에 저장한다.
- 행 배치를 바꾸면 직접 그린 LAN·POWER 구간을 모두 지운다.
- 확대하면 칸 안에 LAN 번호와 연결 순서(몇 번째)만 줄 나눠 크게 표시하며 가로·세로 픽셀 정보는 표시하지 않는다(`render.js`의 `DETAIL_MIN_PX`). POWER 탭은 POWER 포트 번호와 해당 포트의 연결 순서(몇 번째)만 표시하며 픽셀 정보는 표시하지 않는다. POWER 도면에는 전원 그룹 중간 점·그룹 라벨·범례를 표시하지 않는다.
- 입력값·패턴·직접 그린 줄·행 배치는 URL과 localStorage에 저장된다. 상태가 깨진 URL/저장값으로 열어도 멈추면 안 된다
  (잘못된 값은 오류 메시지로 처리, `calc`에서 예외를 던지지 않는다).

## 미확정 / 대기 중

- 세부내역의 캐비닛 수 위에 선택한 픽셀피치명을 항목명으로 표시하고, 값은 LED 가로 × 세로 × 두께, 비고는 `mm (가로 × 세로 × 두께)`로 표시한다. 제품별 두께는 `data/pixel.json`의 `thicknessMm`에 저장한다. 확정값: P1.5 JHT 88mm, P2.6 UNILUMIN 83mm, P3.9 JHT 88mm, P3.9 ABSEN 85mm, P4.8 UNILUMIN 74mm. P2.6 flexible WISDOM은 본체 두께 73mm이며 `잠금장치 포함 두께 약90mm`를 비고와 3D 안내에 표시한다. 본체 두께와 설명은 `pixel.json`의 `thicknessMm`, `thicknessNote`에 저장한다.
- p3.9 야외 500×500 박스는 수량이 일정하지 않아 자동 산출하지 않는다.
- LAN 줄별 표의 `픽셀 합계` 표시는 유지하고 있다.
- 캐비닛 규격의 직접 입력(custom) 선택은 제거했다. 기존 URL/저장값의 custom은 500×500으로 전환한다.
- 사각형 분할 때문에 실제 LAN 줄 수는 용량 하한(전체 픽셀 ÷ 한도)보다 많아질 수 있다. 자재표의 LAN포트 수는 실제 도면 줄 수를 따른다.
- 배포: 사용자가 따로 요청할 때 진행. 필요한 것은 README(폴더 구조, 올리는 방법)와
  Jekyll `_config.yml`의 `exclude`에 `test/`, `package.json`, `start.bat`, `serve.py`, `AGENTS.md` 추가.

## 작업할 때 주의

- 사용자가 LAN(랜선)를 지정하면 LAN만, POWER를 지정하면 POWER만 수정한다. 한쪽 요청을 다른 쪽에 확대 적용하지 않는다. 두 배선 모두의 변경은 사용자가 명시적으로 요청한 경우에만 진행한다.
- 규칙/상수를 코드 곳곳에 하드코딩하지 말고 `config.js` 또는 `pixel.json`에 둔다.
- 셸에서 한글과 `\n`이 섞인 스크립트를 한 줄로 실행하면 이스케이프가 깨지기 쉽다. 파일로 저장해서 실행하는 편이 안전하다.
- 화면 변경은 가능하면 실제 브라우저(예: headless Edge)로 확인한다. 모바일 폭(≈500px)에서도 넘치지 않아야 한다.
- 사용자는 단계마다 실행해 확인하고 짧게 보고받기를 원한다.
